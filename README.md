# datlas

A code generator that turns Go struct schemas into typed Go code for three kinds of data
(see [DESIGN.md](DESIGN.md)):

- **Fixture**: instance-based factories for test data (`datlas fixture`)
- **Master Data**: application-defining YAML compiled into Go values (`datlas master`)
- **Seed Data**: per-environment YAML compiled into Go values (`datlas seed`)

YAML is validated strictly when the code is generated. Nothing parses YAML at runtime.
A complete example lives in [example/](example).

## Installation

Register datlas as a tool of your module (Go 1.24+) and call it from `go:generate`:

```sh
go get -tool github.com/moznion/go-datlas/cmd/datlas
```

```go
//go:generate go tool datlas master
```

datlas requires Go 1.26. Generated fixture factories import
`github.com/moznion/go-datlas/fixturekit` from the same module, so the generator and its runtime are
always resolved to the same version. `fixturekit` itself uses only the standard library.
Generated master and seed data have no dependencies at all.

## Commands

```
datlas fixture [-out DIR] [-pkg NAME] [-config FILE] [-check] [PACKAGES...]
datlas master  [-dir DIR] [-check] [PACKAGE]
datlas seed    [-dir DIR] [-check] [PACKAGE]
datlas version
```

- `-check` does not modify the generated file and fails when it is out of date or stale. Use it in CI.
  (Validating `encoding.TextUnmarshaler` values still builds a program in a temporary
  `.datlas-check-*` directory of the package, removed afterwards.)
- When no annotated type remains, the previously generated file is removed.
- Files not generated by datlas are never overwritten or removed.

## Fixture

```go
package model

//datlas:fixture
type User struct {
	ID        uuid.UUID `fixture:"uuid"`
	Email     string    `fixture:"email"`
	Tags      []string  `fixture:"word,count=3"`
	Company   Company   `fixture:"nested"` // Company is also a //datlas:fixture type
	CreatedAt time.Time `fixture:"now"`
	Note      string    // untagged fields keep their zero value
}
```

```go
// fixture/doc.go
package fixture

//go:generate go tool datlas fixture ../model
```

```go
f := fixture.New(fixture.WithSeed(42), fixture.WithNow(now))
u := f.User()
u = f.User(func(u *model.User) { u.Email = "x@example.test" })
us := f.Users(3)
f.Faker().Sentence() // ad-hoc values
```

Options:

| Option | Effect |
| --- | --- |
| `WithSeed(seed)` | Deterministic values. Without it, the seed comes from `DATLAS_SEED` or is chosen randomly. |
| `WithT(t)` | Logs the seed when the test fails: `fixture seed: 123 (rerun with DATLAS_SEED=123)`. `f.Seed()` returns it too. |
| `WithNow(t)`, `WithClock(fn)` | Fixes the clock used by `now`, `past` and `future`. |
| `WithTimePrecision(d)` | Truncates generated times (default: microseconds, which survive most databases; `0` keeps full precision). |

Tags (`fixture:"generator,param=value,..."`):

| Generator | Field types | Parameters |
| --- | --- | --- |
| `uuid` | `[16]byte`-based types (e.g. `uuid.UUID`), `string` | |
| `email`, `username` | `string` (unique within a factory) | |
| `name`, `first_name`, `last_name`, `word`, `sentence`, `url`, `phone` | `string` | |
| `alpha`, `alphanum` | `string` | `len` (default 16) |
| `int` | integer types | `min` (default 1), `max` (default 1000000) |
| `float` | float types | `min` (default 0), `max` (default 1000) |
| `bool` | `bool` | |
| `now`, `past`, `future` | `time.Time` | |
| `seq` | integer types, `string` | `prefix` (strings only) |
| `oneof=a\|b\|c` | string, integer, float and bool types | |
| `nested` | a `//datlas:fixture` type; builds it with its factory method | |
| `enum` | a `//datlas:enum` type; picks one of its constants | |
| `gen=FUNC` | any type `FUNC` returns (see [Custom generators](#custom-generators)) | |
| `from=PATH` | the type of the field at `PATH` (see [Linked fields](#linked-fields)) | |

- `unique` makes the values of a field distinct within a factory: `fixture:"word,unique"`. The value is
  drawn again while it repeats an earlier one, so it suits generators with many values (`uuid`, `alphanum`,
  wide `int` ranges, `past`, ...). Generators with few values run out: `word` has 26, `first_name` 20,
  `oneof` and `enum` as many as their candidates, and generating more panics with the field name.
  Factories of the same type (`User`, `AdminUser`) share the values, like `seq`. `email`, `username` and
  `seq` are always unique; `now` and `bool` cannot be unique. With `gen`, the type must be comparable. Hand-written methods can use
  `fixturekit.Unique(f.Faker(), "key", f.Faker().Word)`.
- Named types (`type Status string`), pointers (`*T`) and slices (`[]T`, `[]*T`) of supported types work.
  Slices take `count=N` (default 1).
- `oneof` candidates of a `//datlas:enum` type must be constants of that type.
- Untagged embedded structs (e.g. a shared `Timestamps`) are walked: their tagged fields are generated.
  When the embedded type is unexported and in another package, its fields are set through promotion
  (`v.CreatedAt = ...`). An embedded fixture type can use `nested`. An embedded pointer with tagged
  fields must be tagged `nested` or `-`.
- `email` and `username` include a token derived from the seed (`alice.smith.k3x9q2.1@example.test`),
  so factories with different seeds do not collide, e.g. in a shared test database. `seq` restarts at 1
  in each factory.
- Rename factory methods with `//datlas:fixture name=AdminUser` (and `plural=AdminUsers`), e.g. when two
  packages both have a `User` fixture type.
- The output package must not already declare `Option`, `New`, `Factory` or the `With...` options.
- In tag values, a backslash escapes `,` and `|`. Inside a Go struct tag the backslash itself is
  written twice: `fixture:"oneof=a\\,b|c"` yields the candidates `a,b` and `c`.
- Nested fixtures must not form a cycle.
- `wrap=FUNC` passes the generated value to a function, for field types such as `sql.NullString`
  or go-optional's `Option[T]` (see [Wrapper types](#wrapper-types)).
- Fake data is English only.

### Types you cannot annotate

Types generated by other tools (e.g. the structs sqletch or sqlc generate from DDL) cannot carry
`//datlas:fixture` or `fixture` tags: regeneration removes them. Give their policy in a YAML file
instead, which refers to the types and leaves them untouched:

```yaml
# fixture/fixture.yaml
types:
  - type: github.com/example/app/db/gen.InsertUserParams
    name: User            # factory method name (default: the type name); plural: works too
    fields:
      ID: uuid
      Email: email
      Age: int,min=18,max=99
      Bio: sentence,wrap=nullString
      Note: "-"           # explicitly left at its zero value
```

```go
//go:generate go tool datlas fixture -config fixture.yaml ../model
```

- Policies use exactly the tag grammar.
- **Every field the factory can set must be listed** (`"-"` leaves it zero). When the other tool adds a
  column, generation fails instead of silently leaving the new field zero. Unknown fields fail too.
- A type may be listed several times under different names (e.g. `User` and `AdminUser`); such a type
  cannot then be the target of `nested`.
- PACKAGES may be omitted. Only the packages in PACKAGES are scanned for `//datlas:fixture`.

### Wrapper types

`wrap=FUNC` passes the generated value to `FUNC`, which must be `func(X) W` where `W` is assignable
to the field. The generator is checked against `X`.

- `FUNC` is `import/path.Func`, or `Func` for a function of the output package.
  A qualified function's package must be loaded: listed in the policy file's types, in PACKAGES,
  or imported by them.
- A generic function is instantiated with the type arguments of the field type:
  `sql.Null[string]` with `wrap=null` calls `null[string](...)`.
- The field is not decomposed into pointers or slices (wrapper types such as `Option[T]` are slices),
  so `count` cannot be combined with `wrap`.

```go
// fixture/wrap.go
func nullString(s string) sql.NullString { return sql.NullString{String: s, Valid: true} }

func null[T any](v T) sql.Null[T] { return sql.Null[T]{V: v, Valid: true} }
```

### Custom generators

`gen=FUNC` calls `FUNC`, a `func(*fixturekit.Generator) T`, for values the built-in generators do not
cover: domain formats, maps, `time.Duration`, ...

```go
// fake/fake.go
func SKU(g *fixturekit.Generator) string { return "SKU-" + g.AlphaNum(8) }

func Labels(g *fixturekit.Generator) map[string]string { return map[string]string{"team": g.Word()} }
```

```go
SKU    string            `fixture:"gen=example.com/app/fake.SKU"`
Labels map[string]string `fixture:"gen=example.com/app/fake.Labels"`
```

- `FUNC` is resolved like the function of `wrap`: `import/path.Func`, or `Func` for a function of the
  output package. It must not be generic. Using the `Generator` keeps the values deterministic under a seed.
- When `T` is assignable to the field, `FUNC` builds the whole field (a slice, a pointer, a map, ...).
  Otherwise the field is decomposed as usual and `T` must be assignable to its element:
  `[]string` with `gen=...,count=3` calls `FUNC` three times. `wrap` takes the value `FUNC` returns.

### Linked fields

Foreign keys must agree with the records they point at. datlas does not store records, so it offers
two ways to keep them consistent.

`from=PATH` copies another field of the same value, e.g. the ID of a nested fixture:

```go
type User struct {
	Company   Company `fixture:"nested"`
	CompanyID UUID    `fixture:"from=Company.ID"` // v.CompanyID = v.Company.ID
}
```

The parameter `ref=FACTORY.PATH`, added to any generator, generates an option function setting the field
from a value built by another factory. This suits types without nested fields, such as sqlc's `Params`:

```yaml
      AccountID: uuid,ref=Account.ID
```

```go
a := f.Account()                                      // insert it first
ms := f.Memberships(3, fixture.MembershipAccountIDFrom(a)) // AccountID = a.ID
```

- `PATH` is a dotted field path (`Company.ID`, `Profile.Address.City`), relative to the value for `from`
  and to the value of `FACTORY` for `ref`. It must not go through pointers, which may be nil.
- Copies are made after every other field is generated and before opts, so an opt replacing `Company`
  must set `CompanyID` too. A `from` field cannot be the source of another `from`.
- The source must be assignable to the field, or to `T` for a `*T` field (`fixturekit.Ptr` is applied).
  With `wrap`, the source is passed to the wrap function instead.
- Without the option, a `ref` field is generated by its generator as usual. `from` cannot be combined
  with `count` or `unique`.
- The option function is named `<factory><field>From` (`MembershipAccountIDFrom`) and must not clash
  with a declaration of the output package.

### Hand-written factory methods

`Factory` is generated into your package, so methods can be added to it by hand. They share the seed,
the clock and unique values through `Faker()` and can build on generated methods:

```go
func (f *Factory) SuspendedUser() model.User {
	return f.User(func(u *model.User) { u.Status = model.StatusSuspended })
}
```

- A generated method that would clash with a hand-written one fails generation.
  To move a type from a hand-written method to generated code, register it under the same name
  and delete the method.
- `datlas fixture` without PACKAGES and `-config` generates `Factory` without any factory method,
  for projects whose fixtures are all hand-written.
- Hand-written methods are never called for `nested` fields, and added fields are not detected.

## Master Data

```go
package masterdata

//go:generate go tool datlas master

//datlas:master roles
type RoleDefinition struct {
	Code string `yaml:"code" master:"key"`
	Name string `yaml:"name" datlas:"nonzero"`
}

//datlas:master permissions
type PermissionDefinition struct {
	Role   string `yaml:"role" master:"key,ref=roles"` // composite key; must be a role code
	Action string `yaml:"action" master:"key"`
}
```

`roles.yaml` and `permissions.yaml` in the package directory compile into `zz_masterdata_gen.go`:

```go
func Roles() []RoleDefinition
func RoleByCode(key string) (RoleDefinition, bool)
func Permissions() []PermissionDefinition
func PermissionByRoleAndAction(role string, action string) (PermissionDefinition, bool)
```

Every call returns a new copy, so callers cannot modify the master data.
Master data must declare a logical key (`master:"key"`); tagging several fields makes a composite key.
Key fields must be fields of the schema or of a struct inlined into it (`yaml:",inline"`).

Lookup function names use the singular form of the dataset name. Override it when the guess is wrong:
`//datlas:master people singular=Person` generates `PersonByCode`.

Datasets with a single-field key of a string or integer type also get a constant per record, so
application code refers to keys without string literals and a removed key fails to compile:

```go
const (
	RoleCodeAdmin  string = "admin"  // <singular><key field><value>
	RoleCodeMember string = "member" // "read-only" -> RoleCodeReadOnly, -1 -> LevelIDMinus1
)
```

Keys of `//datlas:enum` types (which already have constants) and of `encoding.TextUnmarshaler` types
get none. Two values yielding the same name (`read-only`, `read_only`) fail generation; disable the
constants of a dataset with `//datlas:master roles consts=false`.

`MasterDatasets()` returns the dataset names in dependency order (see [Applying order](#applying-order)).

## Seed Data

```go
package seeddata

//go:generate go tool datlas seed

//datlas:seed users
type UserSeed struct {
	Email      string `yaml:"email" seed:"key"` // the key is optional for seed data
	CompanyKey string `yaml:"company" seed:"ref=companies"`
	Role       string `yaml:"role" seed:"ref=example.com/app/masterdata.roles"`
}
```

Each directory is an environment: `local/users.yaml` and `demo/users.yaml` compile into

```go
func LocalUsers() []UserSeed
func LocalUserByEmail(key string) (UserSeed, bool)
func DemoUsers() []UserSeed
func DemoUserByEmail(key string) (UserSeed, bool)

func SeedDatasets() []string                      // ["companies", "users"], in dependency order
func SeedEnvironments() []string                  // ["demo", "local"]
type SeedSet struct{ Companies []CompanySeed; Users []UserSeed } // fields in dependency order
func SeedFor(env string) (SeedSet, bool)          // for ApplySeedData(ctx, env)
```

Every dataset has an accessor in every environment; environments without a file for it return an empty slice.

## References

`master:"ref=<dataset>"` and `seed:"ref=<dataset>"` require every value of the field to be a
logical key of the referenced dataset. They work on `T`, `*T` (nil is allowed) and `[]T` fields at any
depth (including nested structs, slices and maps of structs), and the target must have a single-field key.
Map keys cannot be references.

- A master data reference points at master data of the same package.
- A seed data reference points at seed data of the same environment.
- `ref=<import path>.<dataset>` points at master data in another package. That package must be
  generated first (`datlas master`), because the keys are read from its generated code.

## Applying order

`MasterDatasets()` and `SeedDatasets()` list the dataset names in dependency order: every dataset
comes after the datasets of the same package it refers to, so inserting them in this order satisfies
foreign keys. The fields of `SeedSet` follow the same order.

- Datasets without an order between them are in name order.
- Datasets referring to each other in a cycle are adjacent, in name order (insert them with deferred
  constraints, or in two passes).
- References of a dataset to itself are ignored: order its records in the YAML file.
- References to master data of another package are ignored: apply master data before seed data.

## Enums

```go
//datlas:enum
type Tier string

const (
	TierFree     Tier = "free"
	TierBusiness Tier = "business"
)
```

YAML values of a type annotated with `//datlas:enum` must equal one of the constants of that type
declared in its package. Enum types may live in any package. They are compiled as literals even when
they implement `encoding.TextUnmarshaler`, and can be logical keys and references. Integer enums are
therefore written with their numeric values (`tier: 2`), not their text form.

## YAML rules

- The YAML files live in the package directory; `-dir` changes that (relative to the package directory).
  Files and directories whose name starts with `.` or `_`, `testdata` directories and directories
  holding Go files (other packages) are ignored. A file named after a declared dataset in a subdirectory
  (up to two levels below the data directory or an environment directory) is an error, since it would not
  be loaded; other YAML files there (deployment manifests, API specs, ...) are left alone.
- Symbolic links are followed, so data can be shared: link a file into several environments
  (`local/companies.yaml -> ../_common/companies.yaml`), or link a whole environment (`e2e -> local`).
  Broken links are errors. (Git checks links out as plain files when `core.symlinks` is off, e.g. on
  some Windows setups.)
- Each file holds one sequence of records.
- Every field is required unless it is a pointer or its `yaml` tag has `omitempty`.
- `datlas:"nonzero"` rejects empty and zero values (`""`, `0`, `false`, `[]`, `{}`, `null`, the zero time)
  and makes the field required. Logical keys are always nonzero.
- Unknown fields, missing required fields, type mismatches, out-of-range numbers, malformed YAML,
  duplicate logical keys, broken references, invalid enum values and YAML files without a schema are errors.
- Supported field types: strings, integers, floats, bools, `[]byte` (written as a string), `time.Time`
  (RFC 3339 or `2006-01-02`, UTC when no zone is given), `time.Duration` (`"1h30m"`), pointers, slices,
  arrays, maps with scalar keys, and nested structs (including `yaml:",inline"`).
  Anchors, aliases and merge keys (`<<`) work.
- Types implementing `encoding.TextUnmarshaler` (e.g. decimal types) are supported: the generator
  builds and runs a small program calling `UnmarshalText` on every value to validate it, and the
  generated code decodes the values when the accessor is called.
